# Исправления ошибок экспорта PDF и Excel

## Описание проблем

### PDF Экспорт
1. **Puppeteer не мог запуститься в контейнеризованных средах** - запуск без аргументов `--no-sandbox` приводил к ошибкам в Docker/изолированных окружениях
2. **Отсутствие обработки закрытия браузера** - browser не закрывался при ошибке, что приводило к утечке ресурсов
3. **Недостаточное логирование** - трудно было диагностировать проблемы
4. **Плохая обработка ошибок на клиенте** - пользователь получал общую ошибку без деталей

### Excel Экспорт
1. **Недостаточная валидация данных** - не проверялась структура `analysis.walls`
2. **Недостаточное логирование** - трудно было диагностировать проблемы
3. **Плохая обработка ошибок на клиенте** - пользователь получал общую ошибку без деталей

## Тестовые сценарии

### PDF Экспорт

1. **Успешный экспорт обработанного проекта**
   - Создать проект, обработать чертеж, экспортировать PDF
   - Ожидаемый результат: PDF файл скачивается успешно
   - Логи: `[PDF Export] Starting export...`, `[PDF Export] Successfully exported...`

2. **Экспорт несуществующего проекта**
   - Попытаться экспортировать проект с несуществующим ID
   - Ожидаемый результат: Ошибка "Проект не найден" (404)
   - Логи: `[PDF Export] Project not found: <id>`

3. **Экспорт необработанного проекта**
   - Создать проект, НЕ обрабатывать чертеж, попытаться экспортировать PDF
   - Ожидаемый результат: Ошибка "Проект не обработан. Сначала выполните анализ чертежа." (400)
   - Логи: `[PDF Export] Project not processed: <id>`

## Важные примечания

### Безопасность Puppeteer
⚠️ **ВНИМАНИЕ**: Использование флага `--no-sandbox` в Puppeteer снижает безопасность, так как отключает изоляцию процессов. Это приемлемо только в следующих случаях:
- Приложение работает в Docker контейнере с ограничениями
- Приложение работает в изолированной среде без доступа извне
- Нет возможности использовать другие методы запуска Chrome

**Рекомендации по безопасности:**
1. Используйте Docker с правильными security настройками
2. Не запускайте сервер от имени root
3. Ограничьте доступ к API через аутентификацию
4. Регулярно обновляйте Puppeteer и зависимости

### Обработка ошибок
Все ошибки теперь логируются на сервере с полным stack trace, что позволяет:
- Быстро диагностировать проблемы в production
- Отслеживать паттерны ошибок
- Улучшать код на основе реальных данных

### Клиентская обработка
Клиент теперь корректно обрабатывает два типа ответов:
1. **JSON ответы с ошибками** - парсятся и показывается точное сообщение
2. **Non-JSON ответы** - показывается HTTP статус и statusText
